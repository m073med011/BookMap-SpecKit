# Implementation Plan: Project Foundation and Architecture

**Branch**: `001-project-foundation` | **Date**: 2026-04-23 | **Spec**: [spec.md](./spec.md)
**Input**: Feature specification from `specs/001-project-foundation/spec.md`

## Summary

Build the complete technical foundation for the BookMap multi-vendor marketplace. This phase delivers: Next.js App Router project with TypeScript strict mode, Tailwind CSS theming (dark/light via next-themes), bidirectional i18n (Arabic RTL / English LTR via next-intl), full shared UI component library (shadcn/ui + Radix UI + CVA), global toast notifications (goey-toast), environment validation (Zod), page-section error boundaries, dashboard shell skeleton, and code quality tooling (ESLint + Prettier + Husky). No business logic, no database tables, no authentication.

## Technical Context

**Language/Version**: TypeScript 5.x with `strict: true`, Node.js 20+
**Primary Dependencies**: Next.js 15 (App Router), Tailwind CSS 4, shadcn/ui, Radix UI, next-intl, next-themes, goey-toast, class-variance-authority (CVA), Zod
**Storage**: N/A (no database in Phase 0; Supabase client utilities created as typed wrappers)
**Testing**: Vitest (unit) + Playwright (E2E)
**Target Platform**: Web (modern browsers, SSR)
**Project Type**: Web application (Next.js App Router)
**Performance Goals**: <3s initial load, <200ms theme switch, <500ms locale switch
**Constraints**: Arabic RTL + English LTR from day one, dark/light theme from day one, all components must work in all 4 combinations
**Scale/Scope**: 18+ shared UI components, 3 route groups, 2 shell layouts (public + dashboard)
**Package Manager**: pnpm

## Constitution Check

*GATE: Must pass before Phase 0 research. Re-check after Phase 1 design.*

| Principle | Status | Notes |
| --------- | ------ | ----- |
| I. Domain-Driven Modular Architecture | PASS | Structure organized by `app/`, `components/ui/`, `components/shared/`, `features/`, `lib/`, `types/`, `schemas/`, `providers/`. Features dir empty in Phase 0; ready for Phase 1+ domain modules. |
| II. SOLID Principles & Clean Code | PASS | Components use composition (Radix primitives + CVA variants). No inheritance chains. Each component has single responsibility. |
| III. Type Safety First | PASS | TypeScript strict mode. Zod validates env vars. All component props fully typed. CVA provides type-safe variants. |
| IV. Security by Design | PASS | No auth/data in Phase 0. Supabase service role key is server-only. Env validation prevents leaked secrets. |
| V. Separation of Concerns | PASS | UI components contain no data fetching. Providers separated from components. Config isolated in `lib/config/`. |
| VI. Internationalization & Accessibility | PASS | next-intl for i18n, URL prefix routing, RTL via Tailwind `rtl:` + logical properties, semantic HTML + ARIA from Radix UI. |
| VII. Realtime with Durable Persistence | N/A | No realtime features in Phase 0. |
| VIII. Migration-Safe Incremental Delivery | PASS | No database. No breaking changes. Foundation is additive only. |

**Gate result**: PASS — all applicable principles satisfied.
